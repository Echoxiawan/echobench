安装与连接帮助

EchoBench 安装包已经内置 Electron、Node.js、Appium、ADB、scrcpy-server 和 CI 构建版 JRE。绝大多数连接问题来自 Android SDK、USB 驱动、设备授权、JDK 或 Xcode 配置。按本页顺序检查，不需要安装额外重复组件。

English
推荐排查顺序

设备已启动 → USB 调试已授权 → adb devices -l 显示 device → Android SDK 路径有效 → JDK 可用 → Appium UiAutomator2/XCUITest 驱动可用 → EchoBench 点击“连接设备”。

先判断缺的是哪一层

安装包内置

不需要单独安装

CI 构建的 EchoBench 安装包通常已包含：

  • Electron 与 Node.js 运行时
  • Appium 与 UiAutomator2/XCUITest 驱动
  • Android Platform-Tools / adb
  • scrcpy-server
  • CI 构建版 JRE
可能需要配置

常见缺失项

  • Windows：Android SDK、Google USB Driver、设备授权
  • macOS：Android SDK、完整 Xcode、iOS 签名
  • Linux：Android SDK、udev 规则、plugdev 权限

Windows：Android 环境

必需Android SDK

安装 Android Studio 和 SDK

  1. 安装 Android Studio。
  2. 打开 SDK Manager，安装 Platform-Tools、Build-Tools、Emulator 和一个 Android Platform。
  3. 默认 SDK 路径通常为 %LOCALAPPDATA%\Android\Sdk。
  4. 设置用户环境变量 ANDROID_HOME 和 ANDROID_SDK_ROOT。
setx ANDROID_HOME "%LOCALAPPDATA%\Android\Sdk" setx ANDROID_SDK_ROOT "%LOCALAPPDATA%\Android\Sdk"

设置后关闭并重新启动 EchoBench，环境变量不会自动进入已经运行的进程。

Android 真机

安装 USB 驱动

Google 设备可在 SDK Manager 的 SDK Tools 中安装 Google USB Driver。国产或厂商设备优先安装对应品牌的 Windows USB 驱动。

Google USB Driver 官方说明

通常内置JDK 17

JDK / Java

CI 安装包会内置 JRE。如果环境体检仍然提示 Java 不可用，可安装 Temurin 17：

winget install EclipseAdoptium.Temurin.17.JDK -e
java -version
内置adb

ADB

EchoBench 默认使用安装包内的 adb。系统 adb 只用于命令行诊断；不要另设错误的 ANDROID_ADB_SERVER_PORT。

adb devices -l adb kill-server adb start-server

macOS：Android 环境

必需Android SDK

安装 Android Studio 和 SDK

安装 Android Studio，在 SDK Manager 安装 Platform-Tools、Build-Tools、Emulator 和 Android Platform。

默认路径：~/Library/Android/sdk。

export ANDROID_HOME="$HOME/Library/Android/sdk" export ANDROID_SDK_ROOT="$ANDROID_HOME" export PATH="$ANDROID_HOME/platform-tools:$PATH"
通常内置JDK

JDK / Java

CI 安装包会内置 JRE。源码运行或需要系统 JDK 时：

brew install openjdk@17 java -version

Linux：Android 环境

必需Android SDK

安装 Android SDK

安装 Android Studio，或仅安装 Command-line Tools 后使用 sdkmanager。默认 SDK 路径通常为 ~/Android/Sdk。

export ANDROID_HOME="$HOME/Android/Sdk" export ANDROID_SDK_ROOT="$ANDROID_HOME" export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH" sdkmanager "platform-tools" "build-tools;35.0.0" "platforms;android-35"
真机必需

USB 设备权限

没有 udev 权限时，adb 常见表现是 no permissions 或设备一闪而过。

sudo usermod -aG plugdev "$USER" sudo udevadm control --reload-rules sudo udevadm trigger

完成后注销并重新登录。厂商设备可参考 官方设备设置说明。

iOS：仅 macOS

macOS完整 Xcode

安装 Xcode

从 App Store 安装 Xcode，至少启动一次并同意许可协议，然后安装命令行工具：

xcode-select --install sudo xcodebuild -license accept xcodebuild -version
真机签名

WebDriverAgent 签名

iOS 真机需要 Apple Developer Team。打开 node_modules/appium-webdriveragent/WebDriverAgent.xcodeproj，为 WebDriverAgentRunner 配置 Team 和 Bundle ID。

然后在 EchoBench 中填写 XCODE TEAM ID、签名身份和 WDA Bundle ID。

iOS 18+

RemoteXPC 隧道

iOS 18+ 真机需要 USB 连接并创建 tunnel。若环境体检或日志提示隧道失败，在 EchoBench 项目目录运行：

sudo node node_modules/appium/index.js driver run xcuitest tunnel-creation
权限

开发者模式与信任

在 iPhone 设置中打开开发者模式，连接后选择“信任此电脑”，并在 Xcode 的 Devices and Simulators 中确认设备可用。

设备准备

Android 真机

  • 连续点击“版本号”开启开发者选项。
  • 开启 USB 调试和“USB 安装”。
  • 连接 USB，解锁屏幕并确认“允许 USB 调试”。
  • USB 模式优先选择文件传输或 MTP。

Android 模拟器

  • 先启动模拟器，再打开 EchoBench。
  • 确认 adb devices -l 中出现 emulator-5554 device。
  • 如果显示 offline，执行 adb reconnect offline。
  • 不要为 EchoBench 单独设置不同的 ADB Server 端口。

环境变量

变量用途建议
ANDROID_HOMEAndroid SDK 根目录指向包含 platform-tools、build-tools、platforms 的目录。
ANDROID_SDK_ROOTAndroid SDK 根目录兼容变量与 ANDROID_HOME 设置为同一路径。
JAVA_HOMEJDK 根目录存在多个 Java 版本时明确指定 JDK 17。
ANDROID_ADB_SERVER_PORTADB Server 自定义端口通常不要设置，默认由 adb 决定。
ADB_SERVER_SOCKETADB Server 自定义 socket仅当已有开发环境明确使用自定义 socket 时继承。

验证命令

Android

adb version adb devices -l java -version echo %ANDROID_HOME% # Windows CMD echo $ANDROID_HOME # macOS / Linux

设备状态必须是 device，不能是 unauthorized 或 offline。

iOS

xcode-select -p xcodebuild -version xcrun xctrace list devices xcrun simctl list devices

常见错误对照

device unauthorized

解锁手机，重新插拔 USB，在“允许 USB 调试”弹窗中点击允许；必要时撤销 USB 调试授权后重新授权。

device offline

执行 adb reconnect offline，重新插拔设备；模拟器可冷启动或切换 ADB Server 默认端口后重试。

ANDROID_HOME / Android SDK not found

安装 Android SDK，设置 ANDROID_HOME 和 ANDROID_SDK_ROOT，完全退出并重启 EchoBench。

java is not recognized / Java not found

安装 JDK 17，设置 JAVA_HOME，并确保 %JAVA_HOME%\bin 或 $JAVA_HOME/bin 位于 PATH。

no permissions（Linux）

配置 Android udev 规则，将当前用户加入 plugdev 组，重新登录后再次运行 adb devices -l。

xcodebuild failed with code 65

WebDriverAgent 签名失败。填写 Team ID，在 Xcode 中为 WebDriverAgentRunner 配置开发团队与 Bundle ID。

RemoteXPC tunnel failed

iOS 18+ 真机请使用 USB，运行 XCUITest tunnel-creation，并确保端口和权限未被其他进程占用。

Appium ECONNREFUSED 4723

打开 EchoBench 日志查看 Appium 启动失败原因，优先检查 Java、驱动安装和端口 4723 是否被其他程序占用。

源码运行环境

只有从源码运行或自行本地打包时才需要以下工具。正式安装包不需要重复安装 Appium、Node.js、adb 或 scrcpy-server。

通用

  • Node.js 22.12+
  • JDK 17
  • Android SDK Platform-Tools
  • scrcpy 3.2（系统命令行诊断）

安装项目依赖

npm ci npm run typecheck npm test npm run desktop:build
修改环境变量后必须重启应用

Windows 的资源管理器启动、macOS Finder 启动和 Linux 桌面启动都不会自动继承新终端变量。设置 SDK/JDK 后请完全退出 EchoBench，再从新终端或重新登录后的桌面环境启动。
