# 同类产品对比

以下按公开产品定位和典型能力做概括，不针对具体版本做功能承诺。

## 适合谁

- 需要在本机快速录制、调试和回放 Android/iOS 流程的 QA 和开发；
- 需要对比多台设备、复现同一操作、做兼容性检查的团队；
- 希望保留测试数据和模型调用自主权的团队；
- 需要从手工步骤过渡到 YAML、WebdriverIO、Python 或 Java 的项目；
- 需要审阅定位器质量和回放失败原因，而不是只接受“成功/失败”的工具。

## 不适合谁

- 需要大规模真机矩阵、云端并行执行和分钟级扩容的团队；
- 需要企业级测试管理、权限审计、报告看板和 Jira/TestRail 深度集成的团队；
- 以游戏、Canvas、强视觉/OCR 场景为主的团队；
- 需要完全无代码、云端 AI 自愈和自然语言执行的团队；
- 需要 Windows 上运行 iOS 自动化的场景。

## 对比表

| 类别 / 代表产品 | 它们通常更强的地方 | EchoBench 的差异 |
|---|---|---|
| 元素检查工具（Appium Inspector） | 元素检查生态成熟，支持附加会话 | 不止检查元素：还能录制、回放、候选校验、多端同步和 AI CSV |
| 开源流程工具（Maestro） | CLI/CI 友好、YAML 流程成熟、社区和文档完善 | 有实时设备画面、交互式录制、定位器候选与实时校验、多设备同步 |
| 图像/游戏测试（Airtest / Poco） | 图像识别、OCR、游戏和自绘 UI、Python IDE | 更偏原生控件树和语义定位，支持多设备协同、AI 用例导出；目前不做视觉识别 |
| Android 专项工具（SoloPi / ATX） | Android 录制、性能采集、生态成熟 | 同时支持 Android/iOS（iOS 仅 macOS）、多端同步、附加会话和元素树；Android 专项深度仍有差距 |
| 商业测试套件（Katalon / TestComplete / Ranorex / Leapwork） | 测试管理、报告、对象仓库、CI 集成、企业支持 | 本地、轻量、可审阅、无许可费用，多设备交互强；测试管理和企业治理需要后续补齐 |
| 云设备农场（BrowserStack / Sauce Labs / LambdaTest / AWS Device Farm） | 真机矩阵、并行、规模、云端报告和集成 | 不上传数据、无云端分钟计费、本地调试方便、支持多设备同步操作；没有大规模并发和云设备覆盖 |
| AI 测试平台（mabl / Testim / TestRigor 等） | 自愈、自然语言、云端执行和分析 | 模型和 Key 由用户提供，数据和流程透明，不锁定厂商；AI 只负责用例整理和 CSV 导出，不做自愈执行 |
| 代码框架（Espresso / XCUITest / Detox） | 执行性能、白盒能力、CI 稳定性 | 低代码录制、实时画面、手工探索和多端同步更适合 QA 起步；工程级速度和可编程性不如代码框架 |

## 核心差异

1. **本地优先**：没有账号、云端队列和第三方设备农场依赖。
2. **定位器可解释**：候选、命中数、推荐/脆弱和回放降级全部可见。
3. **多设备同步**：同一操作广播到多台设备，每台独立实时/同步开关和在线状态。
4. **附加而不接管**：可以连接已有 Appium 会话，脱离时默认不结束别人的会话。
5. **元素树探索**：按节点精确生成定位器，而不是只能从点击坐标猜。
6. **AI 自主可控**：支持任意 OpenAI 兼容接口，也可接本地模型。
7. **脚本可带走**：YAML、WebdriverIO、Python、Java 都可以离开工具运行。
