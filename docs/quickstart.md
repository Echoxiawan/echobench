# 快速开始

## 5 分钟跑通

前置条件：Node.js 22.12+、Chrome/Edge、Android SDK + scrcpy 3.2；iOS 还需要 macOS 和完整 Xcode。

```bash
npm ci
npm run build
npm start
```

打开 `http://127.0.0.1:4710`，选择 Android 或 iOS 设备，点击“连接设备”。Appium 会在第一次连接时自动启动。

完整环境安装见 [安装与依赖](install.md)。

## 首次启动：先做环境体检

打开工作台约 0.6 秒后会自动检查运行环境。缺少必需项时会自动打开 **环境体检**；也可以随时点击顶部 **体检**。

1. 等待检查完成，先看标记为“必需”的未通过项。
2. 可安装的缺失项点击 **安装**；多项缺失时点击 **一键安装缺失项**。
3. macOS 使用 Homebrew，Windows 使用 winget；Linux 会给出对应的 `sudo` 命令，不会静默提权。
4. 项目内置的 Appium 驱动会自动补齐，不需要手动安装驱动。
5. 安装后等待结果自动刷新；如果提示需要重启应用，关闭并重新打开 EchoBench。
6. 点击 **重新检查**，确认当前平台对应的必需项全部通过后，再连接设备。

完整检查项和手动处理方式见 [安装与依赖](install.md#启动环境自检)。

## 连接设备

1. 确认模拟器或真机已启动，且 `adb devices -l` 或 `xcrun xctrace list devices` 能看到它。
2. 左侧选择 **ANDROID** 或 **iOS**。
3. 在“设备”下拉框选择目标设备，也可直接输入设备 UDID。
4. 只操作设备当前前台应用时，“应用路径”、包名和 Activity 可以留空。
5. 要让 Appium 启动指定 Android 应用，填写 `APP PACKAGE` 和 `APP ACTIVITY`；要安装 APK，填写电脑上的 APK 绝对路径。
6. iOS 操作已安装应用时填写 `BUNDLE ID`；安装 `.app` 时填写应用绝对路径。
7. 点击“连接设备”。第一次连接会启动 Appium 和设备驱动，通常比后续连接慢。
8. 等待中间区域显示实时画面，底部状态显示分辨率。

### 连接字段

| 字段 | Android | iOS | 说明 |
| --- | --- | --- | --- |
| 设备 UDID | 必填 | 必填 | Android 为 `adb devices` 序列号；iOS 为真机 UDID 或模拟器 UUID |
| 应用路径 | 可选 | 可选 | 电脑上的 APK 或 `.app` 绝对路径 |
| APP PACKAGE | 可选 | 不适用 | Android 已安装应用包名 |
| APP ACTIVITY | 可选 | 不适用 | Android 启动 Activity |
| BUNDLE ID | 不适用 | 可选 | iOS 已安装应用标识 |

## 录制第一条流程

录制默认关闭。连接设备后，先手动探索页面，需要记录时再开始。

1. 点底部“开始记录”。
2. 直接点击设备画面；点击会发送到设备并新增“点击”步骤。
3. 录制时会自动刷新 iOS 控件树，并用 Appium 实时确认主定位器唯一且落在点击的控件上。
4. 如果候选都不可靠，时间线会显示“定位风险”；选中步骤可查看原因。
5. 在右侧“目标检查器”查看推荐、可用和脆弱候选；可以切换主定位器、点“重新校验”、复制选择器，或用铅笔按钮编辑定位值。
6. 使用左侧方向键记录上下左右滑动；使用中间返回按钮记录返回。方向键滑动会保存默认轨迹的起止坐标和距离。
7. 先选中一个步骤，再点“双击 / 长按 / 放大 / 缩小”记录对应手势。
8. 键盘输入默认开启，直接在设备画面点中输入框即可用电脑键盘打字（支持中文输入法）。停止输入约 0.3 秒后，工具会把这段输入合并成一条输入步骤。
9. 选中滑动步骤后，检查器会显示方向、距离、时长和起止坐标。
10. 步骤列表可以直接拖动排序；选中步骤后可以在检查器里编辑标签和备注。

### 元素拾取

如果只想查看元素而不操作设备，点底部“元素拾取”后再点画面：只读取定位器，不会发送点击；拾取结果可添加为点击步骤。

### 添加断言

在右侧检查器选择条件（出现、可见/隐藏、可用/禁用、选中/未选中、文本、为空、页面稳定），需要时填写期望文本和匹配方式（包含/等于/正则），点击“添加断言”生成独立的 `wait` 步骤。

也可以先用“元素拾取”选中当前页面元素，直接添加断言，不需要先录制点击。选中已生成的断言步骤，可以继续修改条件、期望文本、匹配方式和超时。iOS 文本断言读取控件实际可见文本，`Button` 的 label 也能匹配。

## 回放

点击顶部“回放”从头执行。若想从中间某一步继续：

1. 先在时间线选中该步骤。
2. 点目标检查器里的“从此步回放”。
3. 之前的步骤会标记为“跳过”，进度和统计只计算实际执行的步骤。

设备需要先处于该步骤执行前的页面状态；回放不会自动补齐前面的操作。回放时录制会暂时停止，画面下方展示正在执行的步骤以及“等待控件就绪/等待页面稳定/重试 2/3”等实时状态，右侧为每一步记录执行结果、重试次数、耗时和失败原因。

回放策略（超时、重试次数、页面稳定等待、候选降级）可在右侧“回放策略”中调整，具体字段见 [YAML 脚本格式](yaml.md)。

## 保存和导出

- 点“保存 YAML”下载 `app-steps.yaml`。
- 展开“导出脚本”可下载 WebdriverIO JavaScript、Python 或 Java 测试文件。
- 顶部“设置”里全局配置 AI 接口，之后点击“AI 用例”只需填写用例标题即可导出 CSV。
- 需要排查环境时点击顶部“体检”，在“环境体检”窗口中查看结果。

## 草稿与清空

步骤、项目名称、设备配置和回放策略会自动缓存到浏览器本地，刷新页面会恢复最近一次记录。

点步骤面板右上角“清空”，需要连续两次确认后才会删除当前步骤和缓存；清空后录制保持关闭。

## 附加已有会话

如果会话已经由测试脚本或其他客户端创建，可以在设备面板点击“附加已有 Appium 会话”，填写 Appium Server URL 和 Session ID。附加模式不会创建新会话，也不会在脱离时删除外部会话。

详见 [附加会话与元素树](inspect-session.md)。

## 停止

完成后先点击“断开设备”，再回到启动服务的终端按 `Ctrl+C`。服务会关闭 Appium 会话、scrcpy-server、ADB reverse，以及由本项目启动的 Appium 子进程。

更多清理方式见 [运行日志与清理](operations.md)。
